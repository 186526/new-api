# Web Search and Fetch Rules

Follow these rules when changing the five tool routes, provider selection, caching, or billing. The client path chooses the contract; the selected provider supplies the answer. Keep `tools-search` and `tools-fetch` as protocol-neutral channel capabilities and pricing names. DeepSeek channels intentionally serve the Moonshot-compatible routes through the same capabilities.

## Routing and provider isolation

- `service/channel_select.go` and `service/websearch_group_policy.go` resolve the actual group and tool policy before execution. `disabled` rejects the contract; `inherit` uses global defaults; `prefer` orders eligible providers without excluding unlisted ones; `only` excludes every unlisted provider. In Auto routing, skip disabled groups: if all eligible groups are disabled, return 403; if at least one permits the operation but has no supply, return 503. Fixed-channel and strict-session constraints still apply.
- `service/websearch/abstract` describes contracts, provider capabilities, and ranked candidates. `candidate_order` affects rank, not entitlement or supply. Search excludes `local`; fetch ranks eligible `local` ahead of global Exa by default, subject to configured provider preferences. A Codex channel serving a non-Alpha search needs a valid upstream model mapped from `tools-search`. It sends Codex Alpha Search commands, while the caller receives the requested contract and retains its original billing model.
- `relay/channel` owns `WebSearchAdaptor` request preparation; `service/websearch/request` sends prepared requests and `service/websearch/response` renders non-native answers. On provider or credential-source changes, bind the URL, key, headers, request body and model to the new candidate. Global Exa uses its own endpoint and key. Advertise a new provider operation only with upstream protocol evidence and a response replay; a citation does not establish that the upstream returns fetchable page text.
- `websearch_setting.builtin_fallback_enabled` defaults off. When allowed by the same token, group and route constraints, global Exa or Local Fetch can run without a channel. Use `channel_id=0` for that execution; keep normal pricing and quota checks, with no channel usage or affinity writes.

## Sending, caching and billing

- `request.Forward` sends a provider request once. It returns the first upstream HTTP response, including 408, 429, 5xx and redirects. A later candidate or channel is permitted only when the request is known not to have been sent; unknown delivery is treated as sent. Local page fetch and short-link resolution use their own GET paths. Legacy `retry_attempts` and `retry_base_delay_milliseconds` options do not enable retries in `Forward`.
- The forward cache stores only 2xx responses with nonempty bodies. Keep the cache key bound to the upstream request and credential scope. Negative TTL skips the cache; zero inherits the next default. Protected requests bypass shared forward and redirect caching and request coalescing. Cache invalidation uses generations: stale entries age out by TTL, and an in-flight request cannot populate the new generation. Redis shares invalidation across upgraded instances; in-memory invalidation affects the instance receiving it.
- Keep successful native bodies byte-for-byte for DeepSeek Tools and Codex Alpha. For adapted empty results, render the caller's 200 empty shape and release the precharge; native zero-result Alpha carries no `web_search_preview` tool count. Nonempty Tools and Moonshot answers settle one call; Alpha uses the existing `web_search_preview` billing. Cache hits retain the same contract billing rules.
- Moonshot Search maps an upstream HTTP refusal to an empty compatible result and releases the precharge. Moonshot Fetch preserves the mapped upstream error status so the client can fall back; a successful page without extractable text returns empty Markdown and releases the precharge. Use `service.RelayErrorHandler` and the existing failure refund path for exposed upstream errors. Record refund requests separately from completed refunds.
- When changing routing, transport or settlement, run the relevant tests in `relay/{legacy_websearch_parity,legacy_alpha_search_parity,websearch_pipeline,moonshot_service_handler}_test.go`, `service/websearch/request/transport_test.go` and `service/text_quota_test.go`. Compare the actual upstream call count, status/body, and account effects. Keep raw queries, URLs and credentials out of tool observations.

## Antigravity and Local Fetch

- Antigravity search uses `gemini-3.5-flash-lite` by default. `request/antigravity.go` asks the model to call `googleSearch` and produce `URL || publication time || page title || one sentence in its own words`. Keep the double-pipe delimiter and compatibility with three-column fixtures. Asking for verbatim upstream results trips `RECITATION`; encoding that response has also produced invented fields. Parsing tries URL lines, then grounding citations, then modeled prose. Prose is a fallback, not evidence of a search call.
- Resolve citation short links before rendering, and discard unresolved short links. The redirect cache uses hashed short-link keys. `fillSnippets` reads pages in parallel with a two-second budget for the whole batch, using `request.FetchPageText` so prior Local Fetch cache entries can answer. Keep the model's sentence when a page is slow or has no suitable lead paragraph. Normalize modeled dates to ISO `YYYY-MM-DD` where possible; Moonshot Search always emits `date`, using `null` when absent. Apply `num_results` (or legacy `max_results`) only to rendered Moonshot results.
- Local Fetch uses the configured protected download path and returns Markdown. Keep readable content by dropping hidden subtrees and page chrome; preserve article-owned headers, data tables and fenced-code whitespace. Walk layout tables as blocks. When a dense subtree is only an article stub, fall back to the body. `localFetchStatusError` preserves target HTTP failures for the client; a target connection failure is not a successful empty document.

## Configuration and client contracts

- Manage global defaults and group rules under Operations → Tools Proxy. Read the group policy value and version from `GET /api/tools-api/group-policies` and submit both via `PUT /api/tools-api/group-policies`. On 409, preserve the draft and reconcile it with the returned current value/version. `GET /api/option/` still exposes the legacy value for readers; saves through the generic option interface reject `websearch_setting.group_policies`, including batches containing it. Startup and periodic database synchronization still publish the stored policy. All admin instances must run the versioned writer before relying on conflict protection.
- `setting/websearch_setting` validates and publishes global options and group rules. An empty global order uses the built-in order; `prefer` and `only` require a nonempty, duplicate-free list compatible with the operation. `exa_api_key` is write-only at the generic option interface; use `ExaKeyConfigured` to show credential status. The tools summary and simulation are super-admin operations; simulation resolves eligibility and pricing without sending upstream or charging quota. Cache management at `/api/option/websearch_cache` supports scope and exact invalidation; redirect scope accepts a URL, whereas forward scope accepts a query or URL.
- Kimi Code configuration examples in `/docs#moonshot-service` use `/moonshot.service/v1/search` and `/moonshot.service/v1/fetch`. Search accepts `text_query` and returns `search_results`; fetch accepts `url` and returns Markdown. Native `/v1/alpha/search` uses the client's `model` and `commands.search_query`. Price overrides live in `billing_setting.billing_expr`; built-in `tools-search` and `tools-fetch` rates are in `setting/billing_setting/builtin_billing.go`.
- `model/search_capability_migration.go` idempotently rewrites old DeepSeek and Moonshot search/fetch model names in channel models and token restrictions, rebuilding affected abilities in the same transaction. Retain model-square endpoint metadata for both client contracts when changing the shared capability names.
